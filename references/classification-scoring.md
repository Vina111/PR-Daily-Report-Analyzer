## 1. 内容类型

使用以下互斥主分类：

| 类型 | 定义 | 基础权重 |
|---|---|---:|
| `native_interview` | 媒体独立采写的深度采访或独家 | 1.00 |
| `native_news` | 记者或编辑独立采写的新闻 | 0.90 |
| `native_review` | 独立产品或服务评测 | 0.85 |
| `analysis_opinion` | 评论、分析、专栏或趋势解读 | 0.80 |
| `deals_affiliate` | Deals、Gift Guide、Affiliate 选品 | 0.65 |
| `press_release` | 通稿平台或公司正式新闻稿原文 | 0.45 |
| `press_release_reprint` | 基本未增加独立采写内容的转载 | 0.15 |
| `owned_content` | 公司 Blog、Newsroom、社媒或自有内容 | 0.35 |
| `official_regulatory` | 监管机构、法院或公共机构正式信息 | 按风险规则 |
| `suspected_reprint` | 证据不足但高度疑似通稿转载 | 0.20 |

Sponsored Content 不能归为普通原生报道。根据内容将其标记为 `sponsored` 辅助标签，并在结果中披露。

**输出级强制排除（用户固定规则）**：`press_release`、`press_release_reprint`、`suspected_reprint`、`owned_content` 四类内容仍正常分类和后台计数，但一律不进入任何正式输出（日报、Dashboard、简报、事件卡片、KPI）。它们的价值仅是帮助反查同一事件的原生报道。媒体趋势、声量、统计均只基于原生报道计算。

**来源范围（用户固定规则）**：进入输出的记录，其 `publisher` 必须是外媒（注册地与采编团队在中国大陆以外）或国内头部媒体的海外版（Caixin Global、Yicai Global、KrASIA/36Kr Global、China Daily、SCMP、新华社英文版等）。中国大陆媒体国内版内容分类后仅作背景参考，不进入输出。

## 2. 新闻稿与转载识别

依次检查：

1. 是否来自 PR Newswire、Business Wire、GlobeNewswire 等通稿源；
2. 是否出现 “News provided by”“Source: Company”“PR Newswire”等标记；
3. Byline 是记者、编辑、公司名还是通稿平台；
4. 是否包含公司 Boilerplate、媒体联系人、Safe Harbor 或固定免责声明；
5. 标题、段落和引语是否与原始通稿高度一致；
6. 页面 Canonical、URL 或元数据显示原始来源；
7. 是否加入独立采访、事实核查、对比、分析或反方观点。

判断标准：

- 几乎完整复刻通稿：`press_release_reprint`；
- 增加少量导语但主体一致：仍为 `press_release_reprint`；
- 以通稿为线索并完成独立采写：`native_news`，同时记录 `originated_from_press_release: true`；
- 无法确认：`suspected_reprint`，不得强行归为原生。

后台统计必须保留：

```text
通稿原文数量
转载页面数量
由通稿引发的独立原生报道数量
原生报道涉及的独立媒体数量
```

其中通稿与转载数量只出现在数据口径说明中（“本期检测到 N 篇通稿，已按规则排除”），不进入事件卡片和 KPI。

## 3. 媒体 Tier

分别维护综合影响力和行业影响力：

| Tier | 定义 | 权重 |
|---|---|---:|
| `tier_1_general` | 综合、商业或科技头部媒体 | 1.50 |
| `tier_1_industry` | 对目标行业具有强议程设置能力的垂直媒体 | 1.40 |
| `tier_2` | 区域、专业或中等影响力媒体 | 1.20 |
| `tier_3` | 长尾、低影响力或新兴媒体 | 1.00 |
| `aggregator` | 聚合、自动转载或低质量站点 | 0.60 |
| `official` | 官方监管或公共机构 | 不按流量降级 |

Tier 不能只看 UMV。综合考虑：

- 目标受众匹配；
- 行业内引用与议程设置能力；
- 原创采编能力；
- 记者质量与持续覆盖；
- 地区影响力；
- 客户业务重要性。

媒体在不同行业可以有不同 Tier。

## 4. 事件聚类

使用以下信号聚合同一事件：

- 规范化标题相似度；
- 公司、产品、高管和地点；
- 发布时间接近；
- 相同引语、数字或事实；
- 原始通稿或官方公告 URL；
- 正文或摘要语义相似度。

一个事件集群可以包含：

```text
1 个官方来源
1 个新闻通稿
若干通稿转载
若干第三方原生报道
若干评论或社交延伸
```

集群内分别统计类型，不将网页数量当成事件数量。

## 5. 优先级评分

基础公式：

```text
priority =
  relevance
  × content_type_weight
  × media_tier_weight
  × recency
  × risk_or_opportunity_multiplier
```

建议范围：

```text
relevance: 0.20–1.00
recency: 0.60–1.00
risk_or_opportunity_multiplier: 1.00–2.00
```

不要向用户展示虚假的精确小数。后台可计算分数，前台显示：

```text
高优先级
中优先级
低优先级
```

相同分数时依次优先：

1. 官方风险或监管事实；
2. 行业 Tier 1 原生深度内容；
3. 与客户核心业务高度相关的独家或采访；
4. 可能形成 Pitch 窗口的记者趋势；
5. 通稿和转载统计。

## 6. 风险与机会

### 风险

| 等级 | 含义 | 动作 |
|---|---|---|
| `red` | 已发生且可能迅速扩大，或来自权威官方来源 | 立即通知并准备回应 |
| `orange` | 有可靠信号，影响范围尚在发展 | 重点跟踪并准备材料 |
| `yellow` | 早期、单一或低置信度信号 | 观察，不主动放大 |
| `none` | 无明确风险 | 不进入风险区 |

风险升级至少考虑：

- 来源权威性；
- 原生媒体数量及增长速度；
- 是否涉及安全、召回、诉讼、监管、隐私或重大经营问题；
- 是否与客户产品和市场直接相关；
- 是否存在事实争议。

### Pitch 机会

仅在满足至少两个条件时推荐：

- 多家媒体正在关注相同议题；
- 记者近期连续出稿；
- 客户有独特数据、产品、案例或高管观点；
- 新闻节点与客户业务直接相关；
- 现有报道存在明显信息缺口；
- 有清晰的时间窗口。

每个机会输出：

```text
建议角度
目标媒体/记者
建议行动（一句话）
证据来源
```

按用户固定规则，Pitch 建议保持精简，不展开客户可提供材料清单和不建议条件的完整模板，除非用户当场要求详细 Pitch 方案。

## 7. 置信度

使用：

- `high`：官方源或多个独立可靠来源一致；
- `medium`：单一可靠来源或多个间接信号；
- `low`：来源有限、名称歧义或疑似转载。

低置信度内容不得触发确定性结论。显示“待核实”并说明缺少什么证据。
